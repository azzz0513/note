## 白盒测试概念
### 什么是白盒测试
**White box testing** uses the **implementation** of the software to derive the tests. The tests are designed to exercise some aspect of the program code. / **白盒测试**使用软件的**实现**来推导测试。这些测试旨在考察程序代码的某些方面。
**White-Box testing** provides for **coverage of the implementation**, but not of the specification. That is there may be behaviour stated in the specification for which there is no code in the implementation. / 白盒测试提供了实现的覆盖范围，但没有提供规范的覆盖范围。也就是说，规范中可能规定了实现中没有代码的行为。
![[images/Pasted image 20260526220047.png]]

### 白盒测试的原则（principle）
![[images/Pasted image 20260526220108.png]]
1. Test against the implementation 测试执行情况
2. Use test coverage criteria based on the implementation 根据实现使用测试覆盖率标准
3. Develop test cases derived from the implementation 开发从实现中得出的测试用例
4. “Exercise” implementation “演习”执行

### 什么是控制流测试？
Control-flow testing is a structural testing strategy that uses the program’s control flow as a model. / 控制流测试是一种以程序的控制流为模型的结构测试策略。

Requires the tester to have a clear understanding of the logical structure of the program, and even to be able to master all the **details of the source program**. / 要求测试人员对程序的逻辑结构有清晰的认识，甚至能够掌握源程序的所有细节。

Most applicable to new software for **unit testing**. / 最适用于新软件的单元测试。

## Logic Coverage（逻辑覆盖）
```Go
func example(A, B, X float32) float32 {
	if A > 1 && B == 0 {
		X = X / A
	}
	if A == 2 || X > 1 {
		X = X + 1
	}
	return X
}
```

### Statement/Point Coverage（语句/点覆盖）
- Design test cases and work out input values required to ensure that **every source code statement is executed**.（设计测试用例以及需求的输入值确保**源代码的每一行都能被执行到**）
    - Also known as **point coverage（点覆盖）**
- The **weakest logical coverage**, be used interoperatively with other testing methods.（最弱的逻辑覆盖，一般结合其他的测试方法进行使用）

例：

| ---- | ----------- | ------ | ----- |
| 1    | 2,0,4       | sacbed | 3     |

#### Decision/Branch/Edge Coverage（决策/分支/边覆盖）
- Design test cases and work out input values required to ensure that **every source code branch is taken**.（设计测试用例并且输入需要的的输入值去确保**每一个源代码的分支都可以被执行到**）
    - Each true and false branch of the program is executed at least once（程序中的每一个 true 和 false 分支都可以至少被执行一次）
- Also known as **edge coverage**.（边覆盖）

例：
I 用蓝笔表示：A = 3, B = 0, X = 1, sacbd
II 用红笔表示：A = 2, B = 1, X = 1, sabed
满足分支覆盖一定满足语句覆盖
但是满足语句覆盖不一定满足分支覆盖

#### Condition Coverage（条件覆盖）
- 一个复杂的**决策**是由**许多布尔条件**组合而成的
- 条件覆盖在分支覆盖的基础上做了拓展：**对于复杂的决策，每一个布尔条件的 True 和 False 都应该被测试**
- 这存在一个 caveat （警告）：决策本身的 True 和 False 并没有必要被考虑进去
- 测试数据被选择去确保每一个决策的每一个条件的 True 和 False 都应该被考虑进去

#### Decision Condition Coverage（决策/条件覆盖）
生成测试数据，使决策中的所有条件至少对两个结果（如果可能）进行一次，并练习每个决策的真假结果。
- **每个决策**都有True和False测试用例
- 此外，决策中的**每个条件**都有True和False测试用例（如果可能）
它是**条件覆盖和分支测试的组合**。它使用与条件覆盖相同的测试数据，但必须额外确保每个分支或决策都得出真或假的结果。
- 单条件决策：2 个测试用例
- 2-条件决策：2+ 个测试用例

假设我们有这样一段代码：
```GO
if A > 0 && B == 0 {
    // 动作 1：走 True 分支
} else {
    // 动作 2：走 False 分支
}
```
- **判定/决策 (Decision)**：指的是整个 if 后面的大表达式，也就是 (A > 0 && B == 0) 的最终结果。
- **条件 (Condition)**：指的是构成判定的最小逻辑单元（不能再拆分的布尔表达式）。这里有两个条件：条件1：A > 0 和 条件2：B == 0。

1. **决策覆盖 (Decision Coverage) / 分支覆盖 (Branch Coverage)**
**定义：** 确保程序中每一个**判定（整个 if 语句）**的最终结果，至少取到一次“真 (True)”和一次“假 (False)”。  
（换句话说，确保代码逻辑的每一条“岔路口/分支”都被走过一次）。
**目标：** (A > 0 && B == 0) 整体为 True 一次，整体为 False 一次。

**测试用例设计：**
- 用例 1：A = 1, B = 0。此时 (True && True) -> **整体判定为 True**（覆盖 True 分支，执行动作 1）
- 用例 2：A = -1, B = 0。此时 (False && True) -> **整体判定为 False**（覆盖 False 分支，执行动作 2）

**评价：** 达到了 100% 的决策/分支覆盖。我们验证了程序的两条主干路线。

2. **条件覆盖 (Condition Coverage)**
**定义：** 确保判定中的**每一个独立条件（子条件）**，都至少取到一次“真 (True)”和一次“假 (False)”。它不关心整个 if 语句的最终结果是什么。
**目标：**
- 条件1 A > 0 必须为 True 一次，False 一次。
- 条件2 B == 0 必须为 True 一次，False 一次。

**测试用例设计：**
- 用例 1：A = 1, B = 1。
    - 条件1 1 > 0 是 **True**
    - 条件2 1 == 0 是 **False**
    - 注意：此时 (True && False)，整体判定结果为 **False**。
- 用例 2：A = -1, B = 0。
    - 条件1 -1 > 0 是 **False**
    - 条件2 0 == 0 是 **True**
    - 注意：此时 (False && True)，整体判定结果也为 **False**。

**评价（严重缺陷）：**  
上面这两个用例，完美达到了 **100% 的条件覆盖**（条件1有了T和F，条件2也有了T和F）。  
但是！这两个用例导致整个 if 语句的结果都是 False。**代码中的“动作1（True分支）”根本就没有被执行到！**

决策/条件覆盖的实现步骤：
① 确定程序中所有的决策（decisions）
② 将程序中所有的条件（conditions）列出来
③ 生成测试数据去**覆盖以上的所有决策和条件的布尔值**

#### 优势和不足
##### 优势
- The true and false outcomes of every decision and every condition are covered
- This gives **stronger coverage** than just Condition Coverage or Decision Coverage
- 覆盖每一个决策、每一个条件的真假结果
- 这提供了比条件覆盖或决策覆盖**更强的覆盖范围**

##### 不足
- Even though every decision is tested, and every condition is tested, **not every possible combination of conditions is tested**.
- 即使每个决策都经过测试，每个条件都经过测试，但**并不是每个可能的条件组合都经过测试**。

### Condition Combination Coverage（条件组合覆盖）
#### 定义
Tests are generated to cause **every possible combination** of conditions for **every decision to be tested**. / 生成测试以导致测试**每个决策**的**每个可能条件组合**。
The goal is to achieve **100% coverage** of every decision and **100% coverage** of every condition. 
A **Truth-Table（真值表）** is the best way to identify all the possible combinations of values.

#### 优势和不足
##### 优势
- Tests all possible **combinations of conditions** in every decision.
- 测试每个决策中所有可能的条件组合。

##### 不足
- Can be **expensive**: n conditions in a decision give 2^n test cases. / 可能很昂贵：决策中的n个条件给出2^n个测试用例。
- Can be **difficult** to determine the required input parameter values. / 可能难以确定所需的输入参数值。
- Even though multiple condition testing covers every possible combination of conditions in a decision, it does **not cause every possible execution path** to be taken. / 即使多个条件测试涵盖了决策中所有可能的条件组合，**也不会导致采取所有可能的执行路径**。

### 方法论
涉及到白盒测试的流程覆盖
1.  **先画流程图**
画了流程图可以解决哪两种覆盖呢？**语句覆盖（点覆盖）**、**条件覆盖（边覆盖）**
条件覆盖一定能保证语句覆盖，反之不成立。
2.  **拆解决策和条件**

**条件覆盖：** 只需要让测试用例覆盖确保**条件表** 所有的 True 和 False 至少出现一次
**决策条件覆盖**：让测试用例覆盖确保**决策表和条件表**所有的 True 和 False 至少出现一次
**条件组合覆盖**：以决策为单位，每个决策下面的条件画出 2^N 行的真值表，删掉相互矛盾的行，剩下的写出对应的测试用例进行测试即可

### Path Coverage（路径覆盖）
#### 定义
Generate test data to exercise all the distinct paths in a program. This is called “**path coverage**” / 生成测试数据以练习程序中所有不同的路径。这称为“路径覆盖”

Path coverage causes every possible path from entry to exit of the program to be taken during test execution. / 路径覆盖导致在测试执行期间采取从程序进入到退出的所有可能路径。

The goal is to achieve **100% coverage of every start-to-finish path** in the code. / 目标是实现代码中每个从头到尾的路径100%覆盖。

A path that makes i iterations through a loop is distinct from a path that makes i+1 iterations through a loop, even if the same nodes are visited in both iterations / 通过循环进行i次迭代的路径与通过循环进行i+1次迭代的路径不同，即使在两次迭代中都访问了相同的节点

Thus, there can be an **infinite number of paths** in some programs! / 因此，在某些程序中可能有无限数量的路径！

#### 路径等价类
Need to limit the number of paths: choose equivalence classes of paths（需要限制路径的数量，可以**选择路径的等价类**）
如果两条路径仅在循环迭代次数上不同，则认为它们是等效的，给出了两类循环：
- 一个0次迭代
- 一个有n次迭代（n>0）
如有需要，也可选择其他等价路径
